## Key question: does the run → construct mapping rest on STATED evidence?
**Yes.** The `annotated` status is justified.

The evidence chain:
1. **The submitter's own file names are the construct names.** The depositor named the two raw runs `3HA-BioID2-TbUnc119.wiff` and `TbUnc119-BioID2-HA.wiff`.
2. **The submitter's own PX description defines those exact strings** as the N-terminal and C-terminal fusions. The paper uses the same names with the same definitions.
   - Points 1 and 2 together are an explicit statement by the submitter, not a curator inference.
   - In campaign terms, the run→sample key is printed in the deposit. Nothing is guessed or decoded.
3. **The submission file map ties each search and peak file to its own raw file** (README IDs 10/11 → 12–14 and 16/17 → 15, 18, 19). The `.dat`/`.group`/`.mgf` files therefore cannot be cross-wired between constructs.
4. **The original acquisition names do not contradict the mapping.**
   - The 3HA search used `180121_HYM_HA_UNC119_2ul`: HA before UNC119, which fits the N-terminal 3HA tag.
   - The HA search used `180613_CYN_SPl3_UB_1hr_5ul`. This name does not identify the construct, but it is not evidence against it either.
   - On the "renaming" concern: the original names were never presented as sample keys. The submitter's deposited names are what the repository declares.
5. **Independent consistency checks support the mapping and argue against a swap** (supporting only, not needed for `annotated`):
   - Size asymmetry: the 3HA `.mgf`/`.dat` are 16 MB/21 MB, against 3.0 MB/7.9 MB for HA. This fits the paper's 136 vs 39 candidates.
   - The HA `.dat` contains the bait TbUnc119 (Tb927.2.4580).
   - The HA `.dat` contains no TbArl3A (Tb927.3.3450), which matches the paper's "only in 3HA" statement.
   - Caveat: the HA `.dat` does contain the string Tb927.6.3650 (TbArl3C). Mascot `.dat` files list every candidate peptide match, including ones below threshold, so this does not contradict the paper. It is not decisive either way.
   - The 3HA `.dat` (21 MB) could not be loaded in the browser, so its contents were not checked.

**Residual risk.** A swap would need the submitter to have mislabelled both runs, in a way that is consistent with their own description and with the result sizes. That risk is low and does not make the map INFERRED. There is no label channel to map (label-free).

1. **Spec compliance: pass.**
   - Required ms-proteomics and sample-metadata columns are present. Factor value columns come last.
   - (source name, biological replicate, technical replicate, fraction) is unique across rows.
   - `characteristics[treatment]` and `characteristics[sample type]` are licensed through sample-metadata, which ms-proteomics extends.
2. **Ontology integrity: pass.**
   - PRIDE terms: verified against the live OBO.
   - UNIMOD 1, 35 and 39: verified in the deposited Mascot unimod block. The TA/PP/MT values match the search exactly.
   - MS:1000932, MS:1000422, MS:1001251, MS:1000084 and NCBITaxon 5691: standard, current psi-ms and NCBI accessions. NCBITaxon 5691 is also in the PX record.
   - The NT label case differs from the OBO (lowercase "tris(2-carboxyethyl)phosphine (TCEP)" and "methyl methanethiosulfonate (MMTS)"). This is a case difference only (minor F3).
3. **Source evidence: pass.**
   - Instrument: PX record, paper and `.dat` agree.
   - Reduction, alkylation, trypsin and induction treatment: as in the paper's Methods.
   - Tolerances and modifications: as in the deposited `.dat`.
   - DDA: the paper states IDA.
   - Beam-type CID and TOF MS2 follow necessarily from the QqTOF instrument class, which the `.dat` gives as `ESI-QUAD-TOF`. This is an acceptable inference for recommended/optional columns.
4. **File mapping: pass.**
   - Two vendor `.wiff` runs, each with exactly one SDRF row. Their companion `.scan` files are not separate runs.
   - Peak lists and search outputs are correctly not listed as data files. No deposited raw run is missing.
5. **Design consistency: pass.**
   - Two independent single-run BioID experiments, as the paper states: biological replicate 1 and technical replicate 1 each, with distinct source names.
   - The WT negative controls described in the paper are not deposited. The producer report discloses this correctly.
6. **Omission safety: pass.**
   - No value asserts more than the evidence supports.
   - Unstated items (collision energy, m/z range, strain or life stage) are left out instead of guessed. The life stage is in the report because no column is licensed for it.
