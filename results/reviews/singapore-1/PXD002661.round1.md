## Findings

### I1 (important): spec compliance, `assay name`, all rows
- **Problem:** each multiplexed data file carries three different assay names, one per channel. For example, iTRAQ_osm1_peaklist.mzml has `iTRAQ_osm1-iTRAQ114`, `iTRAQ_osm1-iTRAQ115` and `iTRAQ_osm1-iTRAQ116`.
- **Evidence:** spec README.adoc, Row Uniqueness Requirements (lines 529-535):
  - "Each data file MUST have a unique assay name";
  - NOTE: "For multiplexed experiments (TMT, iTRAQ), multiple rows share the same `assay name` since samples are in one MS run. The `comment[label]` distinguishes samples within the run."
  - The BigBio iTRAQ datasets (for example datasets/PXD001566) use one assay name per raw file.
  - The structural validator does not catch this.
- **Correction criterion:** the number of distinct assay names equals the number of distinct data files, with a 1:1 mapping. For example, `iTRAQ_osm1`, `iTRAQ_osm2` and `iTRAQ_osm3` are each shared by the 3 channel rows of that file. Source name + assay name + label stays unique.

### m1 (minor): treatment text and osmolarity source
- **Problem:** the treatment text uses the measured values 277/377/477 mOsm/L. Those values come from the MetaboLights MTBLS214 protocol, not from the PXD record. The PXD description and the abstract give the nominal values 280/380/480 mOsm.
- **Evidence:** MTBLS214 says the same treatment procedure was used for all experiments, so the values are defensible.
- **Correction criterion (optional):** keep as is, or add the nominal values (for example "377 mOsm/L (nominal 380)") so that readers of the PRIDE record can match them.

### m2 (minor): replicate type
- **Problem:** "three replicates" is not explicitly called biological for the proteomics arm.
- **Evidence:** biological is inferred from the MTBLS214 set design (each set is three parallel sub-cultures).
- **Correction criterion:** acceptable as is. The producer report already lists the osmN-to-replicate index as INFERRED, which is the right place to record it.
