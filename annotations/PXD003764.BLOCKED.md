# PXD003764 — BLOCKED

## Exact blocker

The publication resolves the triple-SILAC channel identities, but the deposit does not resolve the per-run instrument and preparation/fraction grouping needed to represent all 206 RAW files without inference. The Methods state that measurements used either an LTQ-Orbitrap XL or LTQ-Orbitrap Elite and include Offgel, GeLC, SCX/TiO2, flow-through, bead re-elution, and stage-tip re-elution runs. The filenames encode partial workflow hints, but no primary source maps each RAW file to one instrument and one injection/fraction series.

## Evidence checked

- PRIDE project record and protocols: `https://www.ebi.ac.uk/pride/ws/archive/v3/projects/PXD003764`
- Complete file listing: `https://www.ebi.ac.uk/pride/ws/archive/v3/projects/PXD003764/files/all`
- Open-access article Methods: `https://pmc.ncbi.nlm.nih.gov/articles/PMC4835898/`
- Europe PMC supplementary archive, including `Data_Sheet_2.XLSX` and `Data_Sheet_1.PDF`. The spreadsheet contains protein/phosphosite result tables, not a RAW-file design map.
- Deposited `MaxQuant_Output.zip` (911,521,855 bytes) is the only non-RAW project file; there is no standalone sample sheet or parameter/file map.
- Community annotation directory: absent (GitHub directory returned 404).

## Mapping facts that were resolved

- Light / Lys0 = wild-type `ΔlysA`.
- Medium / Lys4 = kinase mutant `ΔptkAΔlysA`.
- Heavy / Lys8 = phosphatase mutant `ΔptpZΔlysA`.
- The study used four phosphoproteome biological replicates and three whole-proteome biological replicates.

## Why an SDRF was not written

Broadcasting both registered instruments to every run, guessing instrument from filename case/date, or treating workflow-specific re-elutions as ordinary fractions/technical replicates would create validator-clean but false rows. A supportable SDRF needs the MaxQuant experiment/file table (or equivalent acquisition log) that explicitly maps all 206 RAW files to instrument, replicate, and fraction/injection group.
