# PXD021197 — annotation blocked

## Dataset

- **Title:** COVID-19 proteome profiling reveals resolution of inflammatory pathways and respiratory distress after DNase treatment
- **PRIDE record:** PXD021197
- **Publication:** Fisher J. et al., Mol Cell Proteomics 2021, DOI [10.1016/j.mcpro.2021.100113](https://doi.org/10.1016/j.mcpro.2021.100113), PMCID [PMC8205261](https://pmc.ncbi.nlm.nih.gov/articles/PMC8205261/)

## Evidence recovered

- PRIDE holds 123 RAW files (Q Exactive HF-X, verified in RAW headers).
- The deposited `file_relationships.xlsx` splits them into 57 DDA library runs (pooled, 8 high-pH fractions + unfractionated) and 66 DIA runs, and labels each DIA run only as *Sputum* (24) or *Plasma* (42).
- The deposited TRIC outputs (`plasma.aligned.xlsx`, `sputum.aligned.xlsx`) identify runs by hashed run IDs, not by sample.
- Supplementary Tables S1–S3 (Europe PMC supplementary zip) report samples as BIN1–3, CF1–5, SP1–4 (sputum) and TP1–5 × day (plasma) but never name a RAW file.

## Why no SDRF was emitted

The sputum DIA runs come from COVID-19 patients, cystic fibrosis patients and bacterial-infection patients, and the plasma runs from five patients at multiple days relative to rhDNase treatment. No deposited or published table links a RAW file to its patient, disease group or time point, so disease and time cannot be assigned per row. Matching hashed run IDs to supplementary columns by intensity correlation would be an inference, not a mapping.

A table mapping each DIA RAW file (CK_P200x_nnn.raw) to its sample label (BIN/CF/SP/TP patient and day), or the OpenSWATH run-ID → filename list used to build the aligned tables together with the sample labels.
