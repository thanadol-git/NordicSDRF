## What the supplement actually contains

Supplementary Table 1 is a protein-abundance matrix with columns **Control 1–20** and **PCOS 1–7** (27 individuals, matching the paper). It has no RAW filenames, no run numbers, and no `20180427_…` stems.

Figs 3–4 label the same analysis IDs as **Case 1–7** and **Ctrl 1–20**. Those labels are not the PRIDE file numbers.

Suppl. Tables 2–4 are IPA networks and ROC protein lists. The R script uses placeholder `datasetname.xlsx` sheets, not a file map.

## Blocking gap

No checked source maps each numbered RAW file to a patient or to disease group (polycystic ovary syndrome vs normal). Assigning PCOS to every row would be wrong (a control arm exists). Treating file numbers as patient IDs, or aligning `_01…` with Control 1 / PCOS 1, would invent the map. The combined `CasevsControlPCOS.mzid.gz` is a single search over all 34 RAWs, not a sample sheet.

Age is cohort means in Table 1 only; no per-sample ages exist to annotate even if files were mapped.

## Unblock requirement

A sample sheet that links every `20180427_PCOS_PREGNANCY_PROTEOMICS_##.raw.zip` to the paper's Case/Ctrl (or PCOS/Control) identifier and disease group, and states what the 34 files are relative to 27 patients × triplicate UDMSE (one file per patient, a subset, extras, or bundled replicates).
