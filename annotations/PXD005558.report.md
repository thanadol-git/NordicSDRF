# PXD005558 annotation report — BLOCKED

**Study:** Streptomyces coelicolor quantitative proteome and phosphoproteome analyses (Rioseras et al., Mol Cell Proteomics 2018, doi 10.1074/mcp.ra117.000515). S. coelicolor M145, TMT-10plex, Orbitrap Fusion (Lumos) / Q Exactive HF files, Mascot via Proteome Discoverer 2.1.

**Outcome:** No SDRF written. The dataset cannot be annotated honestly from the available evidence. See `PXD005558.BLOCKED.md`.

## Why
- Every sample is multiplexed (TMT-10plex; 11plex for FtsZ mutants), so an SDRF needs one row per (file, channel) with a sample identity. The channel-to-sample map is not stated in the paper (only "4:3:3 biological replicates"), not in the deposited PD results (default "Sample" per file, no groups, no channel names), and not in any external repository (Data Availability cites only PRIDE).
- The 40 deposited RAW files cannot be assigned to plexes, fractions or workflow type (total proteome, phospho, FtsZ mutants) from the record. One PD workflow also lists a non-deposited raw (UHF2538.raw). PRIDE marks the submission PARTIAL.
- Supplementary xls tables (likely carrying per-channel columns) are served only behind a JavaScript proof-of-work gate; I did not circumvent it.
- Inventing channel identities is prohibited, so nothing was annotated; no file is partly annotatable.

## Sources exhausted
PRIDE record and file list; PMC HTML full text; Europe PMC full text and supplementary endpoints (not open access); NCBI efetch (front matter only); `QHF0722.pdResult` SQLite; `QHF0722` and `FUS04146` pep.xml logs. Corpus check: no existing directory for PXD005558 in sdrf-annotated-datasets (new).
