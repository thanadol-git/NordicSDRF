## Limitations

- The deposit holds only archives (LC-MS_files_exp1.zip, LC-MS_files_exp2.zip, txt_exp1/2.zip) plus mqpar xml files; run names were read from the zip central directories, not from the PRIDE file list.
- The deposit was split into -exp1 and -exp2 SDRFs because the RAW headers show different instruments (Q Exactive Plus + EASY-nLC vs Q Exactive HF + Evosep), different NCE, MaxQuant versions and fasta files. No single PXD063561.sdrf.tsv exists.
- Which run is which protein sample (WT albumin, LX, QMP, QMP-LX, GLP-1/FIX/ACE2/scFv fusions) and whether it was exposed to carboxypeptidase A is NOT decodable from the deposit or the paper; no treatment or variant columns were added, and no factor value. MaxQuant evidence suggests exp1 runs are dominated by an scFv-HSA entry and exp2 by HSA_WT, but this was not used as annotation.
- The paper and PRIDE state Q Exactive HF and MaxQuant 2.0.3.0 for the whole dataset; the exp1 RAW headers and parameters.txt (MaxQuant 1.6.1.0, 2018, different fasta) contradict this, so exp1 follows the deposited files.
- Biological replicate is 1 for all rows only because no replicate structure is documented; technical replicate 1, fraction 1.
- Fragment tolerance is the MaxQuant FTMS default (20 ppm), not stated in the paper prose.
- PRIDE organism list includes Mus musculus; no mouse material is identifiable among the analysed MS runs, so it is not annotated.
- Search files were read: mqpar_exp1.xml and parameters.txt; the exp1 MaxQuant fixed modification is read from the XML directly because the search-params tool omitted it.
- SANDBOX RECOMMENDED (review PASS, but sample identity unresolved): MaxQuant experiment names are bare integers and the paper gives no run-to-file key for the albumin variants/carboxypeptidase A treatment, so rows cannot be distinguished biologically.
