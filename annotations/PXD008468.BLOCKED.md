# PXD008468 annotation blocked

PXD008468 is "Plasma proteomics reveals the confounding effect of heparin administration on the analysis of candidate cardiovascular biomarkers - Cohort2" (Hans Christian Beck, Dept. Clinical Biochemistry and Pharmacology, Odense University Hospital, Denmark; PRIDE submission type PARTIAL). The paper is Beck HC et al., Clin Chem 2018;64(10):1474-1484 (PMID 30115630, doi:10.1373/clinchem.2017.282665). Cohort 2 is the cross-sectional validation study. It covers 500 admission plasma samples from patients with suspected STEMI; 363 of them received heparin before admission. Samples were enriched on p-aminobenzamidine agarose, digested with trypsin, labelled with TMT 10-plex and fractionated. They were run on a Q Exactive.

## Blocker

No TMT channel-to-sample map exists in any reachable source. The compared variable is heparin-treated versus untreated, a per-patient property. The deposit does not record which patient, or which heparin status, sits in each reporter channel of each sample set. The protocol says only that a pool of 80 untreated patients was always labelled TMT 126. The 500 individual patients were "randomly labelled" with 127N, 127C, 128N, 128C, 129N, 130N and 130C across 63 sets. With no map, every individual channel would carry `not available` for its sample and for the factor. A file like that cannot express the study design, and `build` correctly refuses an invented channel identity.

There are two further problems:
- **Channel usage is ambiguous.** The protocol text says every run held "eight individual labeled samples and two appropriate pools". But the cohort 2 description lists only one pool channel (126) plus seven individual channels, and 129C is never assigned. The real channel set per run cannot be fixed.
- **Fraction numbering is unknown.** Files are named `Sample_<set>_<well>.raw`, for example `Sample_5_GC8.raw`, and the well codes look like autosampler plate positions. The 99 RAW files cover 56 set numbers (1 to 70), with 1 to 4 files per set. That is a partial subset of the fractions. Nothing in the deposit maps a well code to a fraction number. The pdResultView path is `...\Heparin_70_samples02052017\...`, which points to 70 sample sets, not the 63 in the protocol.

## Channel-map ladder (rungs checked)

1. **Paper and supplementary:** The paper is not open access. Europe PMC shows `inPMC=N`, `isOpenAccess=N`, `hasSuppl=N` and no PMCID. The publisher page (academic.oup.com) returned HTTP 403, and no full text or supplementary table could be reached.
2. **Deposited PRIDE files:** There are 99 RAW files and `Heparin_FINAL.pdResultView` (350 MB). I read the pdResultView's SQLite schema by HTTP range requests. It is a view file and holds only subset and sort tables (`ReportInfo`, `DataTypeSubsets`, `TargetPsms_Subset_1`, ...). It has no study-information, sample-group or reporter-channel table. Its `ReportInfo` points to `K:\HeparinDepletion\Final_experiments\Heparin_70_samples02052017\Heparin_FINAL.pdResult`, which was not deposited. RAW headers (first 64 KB of `Sample_5_GC8.raw` and `Sample_1_GB10.raw`) give only the instrument, the method files and the sample name or well (`GB10`). They carry no patient or heparin information.
3. **Europe PMC supplementary:** None, because the paper has no PMCID.
4. **External repositories in Data Availability:** I could not read the paper. The PRIDE record cites no Zenodo, figshare or GitHub resource.
5. **Cross-validation:** Not applicable, because no map was found.

Step 0.5: `bigbio/sdrf-annotated-datasets` has no `datasets/PXD008468` or `sandbox/PXD008468` (both HTTP 404).

## What was established (usable once unblocked)

- Organism `Homo sapiens`. Organism part: blood plasma. Disease context: suspected ST-segment-elevation myocardial infarction (PRIDE lists DOID:9408 acute myocardial infarction). Some patients will not have STEMI confirmed, so the disease would need per-patient evidence.
- Instrument: Q Exactive (MS:1001911). RAW headers say `Q Exactive - Orbitrap MS`, with a Dionex nano-LC. The method files are `70min_HCD30_iTRAQ_res70000_5_28.meth` and `34_min_TFA_LOAD_iTRAQ.meth`. Their names say iTRAQ, but the labelling is TMT according to the protocol.
- Enzyme: trypsin. Reduction with DTT, alkylation with iodoacetamide (fixed carbamidomethyl C). Variable oxidation (M) and deamidation (N). Proteome Discoverer 2.1 with Mascot and SEQUEST, MS1 tolerance 8 ppm, MS2 tolerance 0.05 Da, HCD.
- Labels: TMT 10-plex, with the 126 channel being a pool of 80 untreated patients. The protocol says "6-plex TMT labeling" for the search. TMT6plex and TMT10plex share the UNIMOD:737 mass, so the modification term is unaffected.

## What would unblock it

- A sample sheet giving, for each `Sample_<set>`, the patient (or a pseudonymised ID) and heparin status in each TMT channel, plus which channels each set used. The paper's supplementary or the submitter (hans.christian.beck@rsyd.dk) could provide this.
- The original `Heparin_FINAL.pdResult` with its study-information and sample-group table, if it holds the per-channel groups.
- A map from well codes (for example `GC8`) to fraction numbers for each set.
